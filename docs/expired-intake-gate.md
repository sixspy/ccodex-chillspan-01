# 过期入批门闸取舍（2026-11-22 拍板封死）

## 背景

冷库探头校准到期日后仍能挂新温控批次入库：入批只校验探头在线，不校验校准到期，
过期传感器数据直入正式表 `temp_batches`，对账温区与在批清单按正常批次计绿（假绿），
过期传感器污染正式温谱。

## 拍板：甲路径（唯一口径）

**探头校准已过期 ⇒ 新批次正式表零增并拒写。**

- 入批门闸设在 `POST /api/batches`：探头 `calibration_due < 当日` 一律 409 拒写，
  `temp_batches` 零新增，温度点一律不入正式温谱。
- **乙路径（影子待检批次）永不启用**：本仓不设影子表、不设待检批次、不设晋升流程。
  第三路折中一律不要。两套口径交叉会让过期探头仍出正式批次。
- 拒写同时记审计 `过期入批偏航`（actor、探头、货载入 payload），作为偏离已封取舍的
  偏航痕；任何试图让过期探头入正式表的写法都属于偏航，一律拒写。
- 封批段的 `require_calibration_fresh` 硬拦保留，与入批门闸同属甲路径拒写口径，
  不构成第二口径。
- 探头重新校准（`POST /api/calibrations` 写入新的 `valid_until`）后门闸自动放开，
  这是唯一恢复入批的途径。

## 争用口径（与命运取舍分两段）

1. **争用验收段**：同探头建批先占探头锁 `probe:{id}`（独立事务先提交再办事），
   先到先得；后到只留争用痕（`contention_log`），不写任何业务行。
2. **命运取舍段**：占锁之后才做仓间配额、探头匹配、在线与校准门闸校验。
   两段不得合并：后到者的批次即使合法也只留争用痕。

## 五页同源

探头页、校准页、批次页、对账页、仓间页同读 `temp_batches`+`probes` 单源；
`calibration_expired` / `probe_calibration_expired` 等过期判定一律由服务端
SQL（`calibration_due < date('now')`）给出，前端不做第二套日期判定。
对账页把在批的过期正式批单列 `expired_official_batches` 并判失衡，不再假绿。

## 封死

本取舍自 2026-11-22 起封死。偏离本文件取舍（含暗设影子路径、放松门闸为警告级、
前端自行另判过期）即记 `过期入批偏航` 并拒写。
